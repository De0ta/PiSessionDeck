# 协作与维护约定

## 文档分层

- `workflow/` 只保存四个核心文件：`README.md`、`agents.md`、`plan.md`、`docs.md`。
- `docs/` 是可扩展的详细 Markdown 文档区。
- 新增专题调研、架构、协议、决策和验证文档默认放入 `docs/`，不放入 `workflow/`。
- `workflow/README.md` 记录现在；`workflow/plan.md` 记录后续交付；`workflow/docs.md` 记录事实与约束；本文件记录协作方式。

## 工作顺序

1. 修改前检查当前文件、用户新要求和既有文档，不依据旧状态推测进展。
2. 区分用户提出的目标、用户报告的进展、仓库可见的实现和真正执行过的验证。
3. 开源候选先核对 README、许可证、manifest 和关键源码，再做安装决策；搜索摘要不能独立作为兼容性证据。
4. 在 Windows 原生与 Linux/WSL 间明确边界，不因为 shell 外观相似而跳过平台检查。
5. 用户确认实施范围后再创建插件工程；先做最小入口和浏览器，再扩充管理与后台控制。
6. 每个里程碑后更新当前状态、待办与详细验证记录；不把未运行的测试标为通过。

## 本轮授权边界

- 已授权：调研与工作流、Windows轻量版、本人GitHub私有仓库；全屏配色与帮助改版；最新十项细节、用户手动命名、底栏分色；新增当前模型自动标题/本地回退、最近Prompt、隐藏搜索、r重命名、Prompt地址分色、右键打开和状态文字分色/所有白色按键名/右栏留白与状态圈及工程路径分行。当前会话原生命名属于新增授权范围，历史只写独立别名。用户已追加授权Model/Status分组和Recent六档时间分组；只读模型元数据不增加模型请求或历史写入。用户另行授权按目录截图增加独立恢复页：顶部灰块而非全屏灰色，同/跨目录分开显示，返回保留原列表，草稿/只读预检保护；不伪造当前目录恢复或持久目录偏好。
- v1.0发布授权（已完成）：发布审查两处修复、MIT许可证、Windows/Linux CI、发布文档、v1.0.0标签与GitHub公开Release；可在隔离临时目录运行真实安装/加载，核查Git历史，CI/审查通过后将现有仓库公开。npm发布不在本轮范围。
- 当前 M3 追加授权：`n` 当前 cwd 无 prompt 新建；`f` 当前原生 fork、历史严格快照到新文件再切换；`p` 独立 Pinned；`Delete` 非当前单项永久删除；`a` 菜单，保留输入字母与旧 `r` / `d`。执行边界与隔离验收以[管理专题](../docs/management.md)为准，不含归档、回收站或后台控制。
- 自动标题追加要求：system prompt 禁止标题标签前缀，`cleanModelTitle` 清理“短会话标题-”“会话标题:”“Short session title”等，不改旧标题、不重新请求。
- 文档按职责分工：四份 workflow 核心文件记录主线，具体实现与验收放在 `docs/management.md`。本轮不改包版本；自动化与独立审查不能替代真实终端人工验收，不得将未执行的验收写成通过。
- 未授权：自动安装到用户真实Pi、第三方host、持久后台服务、开发验证中修改真实历史，或超出自动命名范围的模型请求。用户已授权插件运行时使用当前模型拟标题；开发验证仍只用模型替身和临时合成会话，不执行真实付费请求或真实历史命名。
- 外部源码可只读检查；它不属于本仓库代码，不能记作本项目已实现功能。

## 实施时应保持

- 普通光标移动、草稿、自动补全和弹窗交互不得被空输入快捷入口破坏。
- 只在 TUI 模式注册终端交互；保留命令入口作为快捷键不可用时的退路。
- 不通过类型强转绕过命令上下文能力边界；切换后不复用失效上下文。
- 不通过 `process.chdir()` 假装完成跨项目运行时切换。
- 区分取消当前任务、停止受管会话、退出前端；不误伤其他活动实例。
- 测试优先用临时状态目录和无付费模型的假数据；新增真实模型用途和后台驻留须事先说明；命名请求已获授权，但测试不实际发起。
- 复用代码时保留许可证与来源；私有 Pi API 依赖必须单列版本约束。
