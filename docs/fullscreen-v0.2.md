# 全屏 v0.2：设计与验证

> 此文记录v0.2历史交付。新增项目展开、命名、Markdown与配色细节见[v0.3](refinements-v0.3.md)，以当前README和该文为准。

## 本轮范围

按两张新增 Codex 截图实施终端全屏、暗色列表与详情、稳定身份配色及快捷键帮助。保持 Windows 友好的轻量路线：不引入后台 host，不伪造其他 Pi 进程的运行状态，不自动安装，不修改真实历史，不调用模型。

## 页面与生命周期

- 使用公开 `ctx.ui.custom()` 的 overlay 模式，宽/最大高均为 `100%`，定位 `(0, 0)`、边距 `0`。
- 浏览器按实时 `terminal.rows` 输出恰好一屏；每行填满可用列并设置深色背景，包括空白行。窄至一列、低至一行仍不溢出。
- 通过公开 OverlayHandle 检查焦点。其他权限/输入弹窗取得焦点时，同帧隐藏覆盖层并在微任务中关闭浏览器，避免出现看不见却接收按键的底层弹窗。
- 覆盖层不会替换聊天组件。退出通过宿主移除自身 overlay，恢复原焦点；不手动清空终端或恢复旧聊天快照，后台期间的聊天更新仍保留。
- 宽度至少100列时左右分栏：左侧 Tasks / Status / Updated，右侧 Task details；更窄时左右键切列表与详情。
- 标题行、过滤栏和底部简短提示固定。默认全部项目，支持当前项目过滤及项目/最近活动分组；当前会话默认选中。
- 身份色由 session ID 哈希映射至8种柔和颜色，不随选择/排序/刷新变化；不同ID可能同色。选中行统一蓝底深色字。

## 搜索与帮助

| 模式 | 行为 |
| --- | --- |
| 普通浏览 | `F3`搜索，`Tab`/`Shift+Tab`过滤，`g`分组，`?`帮助，`Ctrl+R`刷新 |
| 搜索 | 输入作为查询；`g`、`?`等不触发浏览动作；左右键编辑光标；`Esc`或`F3`退出并清空查询 |
| 帮助 | 显示 Navigate / Tasks / View 三组；宽屏并列，窄屏纵向可滚动；`Esc`/`?`返回 |
| 通用 | `Ctrl+C`直接关闭；普通模式`Esc`关闭；`↑/↓`选择、`Enter`打开；`Shift+↑/↓`滚动详情 |

保留 `Ctrl+O` 切范围兼容键。不显示尚未实现的置顶、归档、删除、工作树、新建后台任务等 Codex 快捷键。

## 语义详情

- 模型、推理级别：来自当前分支的 `buildSessionProjection()`，缺失模型显示 Unknown，不猜测当前全局配置。
- 首问：完整当前分支的第一条 user；最后消息：完整当前分支的最后一条 assistant，仅提取文本，不显示思考、工具调用或工具输出。
- 两个历史字段不会因为压缩或最近8条预览的内部限制而丢失；按完整当前分支的 context_edit 后写优先解析，删除显示省略占位符，空替换不回退到原文。
- 首问/回复分别最多6000字符，之后明确截断；清理终端转义与控制字符。
- 当前会话直接使用内存分支及当前叶节点；其他历史仅只读解析，再以 `SessionManager.inMemory()` 建模。禁止用可能迁移写回的 `SessionManager.open()`。
- 文件读取上限16 MiB。超大、空、损坏、缺失文件和异步过期响应均保留原有安全处理。
- 搜索和列表标题仍来自 Pi 发现API索引；索引可能包含非当前分支/编辑前的历史文本。语义详情的编辑解析不等于对原始历史或索引进行隐私擦除。

## 状态和恢复

仅当前进程会话读取 `isIdle()` / `hasPendingMessages()`，显示 Ready / Working / Queued。其他历史统一 Saved，只说明保存记录，不能推断进程是否活动。`agent_start` / `agent_settled` 更新当前状态；`tool_execution_start` / `turn_end` 在消息持久化后更新详情，避免 Pi 的 `message_end` 扩展回调早于持久化造成旧数据。相同会话更新保留详情内容与滚动位置。不实现跨进程实时监控或每个token的历史同步。

恢复仍遵守：关闭页面 → 空闲/队列检查 → 明确确认 → 再次检查 → `switchSession()`。恢复当前会话仅返回聊天；切换会替换运行时和草稿，不是后台保留任务。

## 自动化验证

- `npm run check`：严格类型检查通过。
- `npm test`：35项通过，包括原21项与新增详情、整屏覆盖、模式快捷键、状态、身份色、极小尺寸、resize、overlay参数、原生焦点恢复、竞争弹窗让出及刷新滚动保持回归。
- `npm pack --dry-run`：v0.2.0入口与源码清单核对通过，包含新增焦点保护模块。
- 独立审查提出竞争弹窗遮挡、消息事件早于持久化、刷新打断滚动三项问题；均已修复，新增相关回归。针对修复的第二轮独立复查未发现其他可操作问题。
- 测试使用合成数据和临时目录，不请求模型、不写真实会话。整屏测试使用ANSI着色与公开行合成器检查无底层文本残留；焦点测试使用不启动、屏蔽输出的终端对象。
- 既有只读文件字节/mtime、分支/context_edit、空/损坏/超大文件、恢复确认竞态、加载器与编辑器兼容测试继续通过。

自动化验证不代表真实终端视觉或完整跨项目运行时端到端验收。

## 待人工验收

1. `pi -e .` 临时加载；空输入`←`或`/session-browser`，确认整个可视区被覆盖，没有底层聊天穿透。
2. 大量聊天和短聊天各测试打开/退出；确认滚屏、草稿和焦点保留，重复开关和`/reload`不残留页面。
3. Windows Terminal resize、分屏、极窄窗口；比较截图中的层级、配色、列宽与留白。
4. `F3`输入中英文、`g`与`?`、左右键和Esc；退出搜索后验证`g`分组、Tab过滤、`?`帮助及滚动。
5. 对可丢弃的分支/压缩/上下文编辑会话核对首问、最后回复、模型/推理及省略占位符。
6. 当前任务运行与消息排队时观察状态；其他历史应一直显示Saved，不能据此认定可安全接管。
7. 仅用可丢弃历史测试确认恢复、取消、跨项目cwd和缺失目录；避免另一实例正在写入的会话。
