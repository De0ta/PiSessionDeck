# v0.5 四种会话分组

## 交互

`g`依次切换`Project → Recent → Model → Status → Project`。初始Project；搜索输入模式中的`g`仍是普通文字。项目范围过滤和搜索先应用，再对命中的会话分组。

每组默认显示5条，`Show more`每次展开5条，组间留空行；`Enter`和`→`仍用于展开或打开会话。切换分组、过滤或搜索时清空展开量，避免把一个分组的分页状态误用到另一个分组。

- Project：按项目目录归组，保持原行为。
- Recent：按最后活动时间`SessionInfo.modified`分六档，非创建时间。
- Model：按完整`provider + modelId`归组，同ID不同供应商不合并。
- Status：按列表显示的状态归组，不推断其他进程状态。

## Recent时间定义

| 标签 | 最后活动距当前时间 |
| --- | --- |
| Within 5 hours | 小于5小时 |
| 5 hours – 1 day | 大于等于5小时、小于24小时 |
| 1 day – 1 week | 大于等于24小时、小于7天 |
| 1 week – 1 month | 大于等于7天、小于30天 |
| 1 month – 3 months | 大于等于30天、小于90天 |
| Over 3 months | 大于等于90天 |

1个月按30天计算，不按日历月；上下限采用左闭右开，90天正好归最后一档。只显示非空组，组按新到旧排序，组内仍按活动时间排序；未来时间按0处理，非法时间单列`Unknown time`。

每次渲染/操作按当前时间重算。没有额外定时器主动唤醒界面。如果一个可见选择因时间经过或实时元数据变化迁入另一折叠组，会按5条步长展开目标组，保证选中的会话仍可见；显式切换分组时仍恢复默认5条。

## Model元数据

Pi 1.4公开`SessionInfo`没有模型字段，不能直接从列表拿到，也不能只取第一条`model_change`。实现采用：

1. 当前进程会话取`sessionManager.buildSessionProjection().model`；`model_select`等事件刷新当前列表与详情。
2. 其他历史只读打开文件，将文本解析为条目，再用`SessionManager.inMemory()`投影当前分支；遵循最后有效`model_change`或助手实际模型，不混入废弃分支。
3. 只有切到Model分组时加载。最多4个并发读取，文件上限16 MiB；按路径和`size/mtimeMs/ctimeMs`缓存，模型切换但活动时间未变时仍重新核查文件修订。
4. 缺失、损坏、过大、缺少模型的会话显示`Unknown model`；仍可选择和恢复。
5. 刷新、切换范围/分组或关闭时取消旧请求；迟到返回不能覆盖新结果或重开页面。文件读取使用只读句柄并在finally关闭，不调用`SessionManager.open()`，不改写历史。

分组键用供应商/模型元组编码，未知模型有独立键；显示名称使用`provider/modelId`。当前分支模型只作为本次浏览的元数据，不把它写回会话或标题。

## Status语义

当前进程使用既有`Ready / Working / Queued / Completed / Stopped / Error`信号；其他历史全部为`Saved`。同一状态聚为一组，当前状态变化时更新；`Saved`不意味着该会话已停止，可能仍由其他Pi进程写入。轻量版不因此新增跨进程监控或接管承诺。

## 人工验收

1. 在可丢弃会话中临时加载`pi -e .`，按`g`确认四模式循环，帮助页与头部名称一致。
2. 用不同活动日期的合成历史核对Recent六组；验证分组内超过5条时`Show more`逐次增加5条。
3. 用同模型/不同供应商/切换模型/无模型的合成历史核对Model；刷新、切组、关闭过程中不应出现旧结果覆盖。
4. 开始/结束当前任务，确认Status组与状态文字一致；历史始终是Saved。
5. 搜索时键入`g`应只输入文本；项目过滤后只对过滤结果分组。宽窄屏下展开、选择和详情仍指向同一会话。
