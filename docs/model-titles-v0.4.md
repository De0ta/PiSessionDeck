# v0.4 模型标题与交互

## 本轮范围

用户确认使用当前模型自动拟标题，失败回退本地提炼；同时要求最新回复对应Prompt、搜索栏默认隐藏、r命名、Prompt地址彩色、右方向键等同Enter打开。后续补充：Status标题灰色/各行状态柔和灰白色，所有按键名白色；右栏标题前留空行、状态前加圈，Reasoning与Project空行分隔，路径独立一行。

本轮验证使用合成数据与模型替身，覆盖模型标题请求和交互逻辑。

## 模型标题

1. `agent_before_settle`只记录最终outcome，不提前读取尚未提交的上下文编辑。仅TUI模式、未取消且成功的`agent_settled`才尝试命名。
2. 已有名称、任何session_info命名记录（包括主动清空）或`pi-session-viewer:auto-title`标记则跳过，包括旧版自动本地标题；不批量重算历史名称。
3. 从当前分支读取首问及首轮最后一个文本回复（不取工具调用前的准备性解说），应用完整分支的最新context_edit，包含删除和空替换。不因右侧详情改为最近Prompt而改变命名输入。
4. 立即保存本地标题与一次性标记，随后启动独立的后台命名请求。即使关闭/reload或请求失败，已有回退仍保留；恢复后不会不断重新请求。
5. 使用公开`ctx.modelRegistry.streamSimple(model, context, options).result()`，复用当前模型及认证、端点和虚拟模型路由。不缓存/手动读取密钥，不引入pi-ai兼容API。
6. 只发送首问最多4000字符、首轮最终文本回复最多2000字符；先完整去掉资源包装块再截断，仅文本，不含思考、工具结果或图片。独立system提示要求把问答视为数据，用用户语言只返回简短标题，不提供工具。
7. 输出最多256 token，不启用可选推理（避免与Anthropic最小thinking预算冲突）、cacheRetention=none、maxRetries=0、timeoutMs=15000，并设置独立AbortController和硬超时。自定义provider或认证刷新不保证只产生一次HTTP请求；本扩展每会话只发起一次命名尝试。
8. 仅接受stop结束且有效的单行文本；过滤控制字符、外围引号/标题前缀，拒绝多行说明和标签，最多42个Unicode码点，超长省略。失败、空响应、长度耗尽、工具调用和超时都保留本地回退，不自动重试。
9. `session_shutdown`在退出/reload/新建/恢复/分叉时中止请求。提交前先检查任务仍有效，再验证会话ID、名称、session_info修订和首轮输入未变；手动改名、改回原名或清空均优先，不接受迟到结果。
10. 名称通过`setSessionName()`写入，成功后追加模型/usage非上下文元数据。不使用sendMessage/sendUserMessage，不把命名请求或标题当成对话消息。额外请求可能计费，其usage保存在扩展custom条目中，不承诺计入Pi主任务原生统计。

已有标题不重算，也不会因为F2改成r而丢失原有名称或历史独立别名。浏览、搜索和详情读取本身不触发模型请求。

## Prompt与渲染

- `Last message`是当前分支最后一条助手消息，Prompt是它之前最近的一条用户消息。排队但还没收到回复的新问题不会与旧回复错配。
- 尚无助手消息时显示最新提问。对应提问被删除则显示省略占位，不回退到首问；尊重空替换，不泄漏原文。
- 仍用Pi原生Markdown；Prompt中的裸URL、Markdown链接及Windows/POSIX/相对路径呈蓝色。支持终端超链接时保留OSC8，不强制把地址再打印一遍。
- 地址着色只处理可见文本，保留渲染器自己的ANSI/OSC序列；原始会话数据仍先清除控制序列。
- Prompt仍固定保留，Shift+上下只滚动最后回复；搜索栏隐藏后回收其所占行，仍按终端高度重新计算分区。

## 按键与分色

| 按键 | 本轮行为 |
| --- | --- |
| F3 | 搜索栏显隐；Esc关闭搜索并清空查询 |
| r | 浏览状态重命名；输入/搜索状态作为普通文本，不触发重命名 |
| Enter / → | 恢复选中会话，或展开Show more；搜索中→保留光标移动 |
| d / ← | 窄屏详情/列表，避免与→打开冲突 |

Status列标题为灰色（#929292），各行状态文字为柔和灰白色（#dadada），Updated仍灰色；选中行仍蓝底，状态圈仍分别使用默认灰、工作蓝、完成绿。详情中的状态同样为灰白色、前置着色圆圈，Current补充说明保持灰色。

底栏、过滤栏、帮助、加载取消提示、窄屏提示等所有按键名使用白色（#ffffff），说明文字仍灰色。右栏Task details下空一行再显示标题；Reasoning后空一行，Project标签与工程路径分别占行。极矮窗口优先保留可读Prompt和回复。

## 操作检查

1. `/reload`后打开浏览器，确认默认无Search条；F3出现，Esc隐藏；搜索中r仍输入字母。
2. r修改名称；→与Enter都进入确认/恢复或展开Show more；窄屏d查看详情、←返回。
3. 使用三轮不同提问的可丢弃会话，确认Prompt对应Last message而不是首问；追加尚未收到回复的问题不应错配。
4. 检查Prompt中的Markdown链接、裸URL、本地路径的颜色，以及Status灰色标题/灰白色状态文字，以及所有按键名白色、新的右栏留白/状态圈/工程路径分行；缩放窗口确认分区仍可用。
5. 仅在接受额外模型费用时，使用未命名的新会话成功完成首轮；先见本地标题，最多15秒内应被简短模型标题替换，失败则保持原样。
6. 生成期间手动命名应保留手动结果；关闭/reload/切换不能将迟到标题写入新会话。已有命名或旧版自动标记不会再次请求。
